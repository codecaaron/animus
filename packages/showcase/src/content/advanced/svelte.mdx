# Svelte 5

Animus supports Svelte 5 through the framework-neutral `.asClass()` terminal.
Keep resolver definitions in JavaScript or TypeScript modules, import them by
name into a native Svelte instance script, call `.attrs()` directly with an
explicit object literal, and spread the result onto a native element.

---

## Setup

The application owns Svelte and its official Vite compiler plugin. Animus's
extract package declares Svelte as an optional peer and loads
`svelte/compiler` only when the host opts into `.svelte` source ingestion.
Projects with no `.svelte` input do not load that compiler.

```ts
// vite.config.ts
import { animusExtract } from '@animus-ui/vite-plugin';
import { svelte } from '@sveltejs/vite-plugin-svelte';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    svelte(),
    animusExtract({
      system: './src/ds.ts',
      runtimeImport: '@animus-ui/system/class-resolver',
      extensions: ['.ts', '.tsx', '.js', '.jsx', '.mdx', '.svelte'],
      strict: true,
      verify: true,
    }),
  ],
});
```

The official Svelte plugin runs first. The Animus plugin reads the original
`.svelte` source through its shared source-ingestion lifecycle; it does not
scan compiler-generated JavaScript.

`runtimeImport` selects the framework-neutral runtime that exposes only
`createClassResolver`. Use this override only when every extracted terminal in
the application is `.asClass()`. Consumers that also extract React component
terminals must keep the default `@animus-ui/system` runtime. React remains an
optional peer of the system package. A production-only install can load the
class-resolver entry without React, and the Svelte canary's client and SSR
production artifacts contain neither React runtime nor system-builder code.

Development and build-time authoring does not require the React runtime
package. The extraction loader evaluates the configured system independently
(React is stubbed there), and the extraction-only binding below keeps the
React-reaching builder barrel out of the application module graph entirely.
The one remaining React artifact is `@types/react@18.3.28`: the root system
entry's declarations still expose React component types, so strict TypeScript
needs the exact types package as a development-only dependency.

This bounded integration uses Svelte's native syntax and the official plugin's
built-in TypeScript handling. Custom preprocessors and preprocessor source-map
composition are not supported.

## Split the build-time system from runtime resolvers

The extractor loads the system and theme while Vite starts. Keep that
build-time module separate and wrap only its top-level builder construction in
explicit pure calls:

```ts
// src/ds.ts
import { createSystem, createTheme } from '@animus-ui/system';

export const theme = /* @__PURE__ */ (() =>
  createTheme()
    .addColors({
      canary: { ink: '#123456' },
    })
    .build())();

export const ds = /* @__PURE__ */ (() => createSystem().build().seal())();
```

Define runtime resolvers in a second TypeScript module through the
extraction-only system binding — a type-only import plus a declared local
chain root:

```ts
// src/definitions.ts
import type { ds as configuredSystem } from './ds';

declare const ds: typeof configuredSystem;

export const notice = ds
  .styles({ display: 'flex' })
  .variant({
    prop: 'tone',
    defaultVariant: 'calm',
    variants: {
      calm: { outlineStyle: 'solid' },
      urgent: { outlineStyle: 'dashed' },
    },
  })
  .props({
    gap: { property: 'gap' },
  })
  .asClass();
```

The configured system keeps its exact type, but the application module graph
never evaluates `ds.ts` — the extraction loader is the only evaluator.
Successful extraction replaces every supported chain with its generated class
resolver before TypeScript erasure removes the type-only import and the
declaration.

<Callout variant="warn" title="This pattern requires strict: true">
  If extraction cannot publish a replacement, the build or development request
  fails loudly instead of serving raw code whose `ds` binding no longer exists
  at runtime.
</Callout>

An ordinary value import (`import { ds } from './ds';`) also remains
supported; extraction leaves it unused and the two pure wrappers let Vite
remove the complete builder module from both client and SSR artifacts. It
costs React as a development dependency, though: in development Vite
evaluates the value-imported builder graph, which reaches React-backed
modules. Do not mark unrelated application work pure.

During development, a system edit can change a definition module's generated
replacement even though the type-only binding leaves no browser import edge.
The plugin's geological reset diffs every file's replacement plan across the
reset and invalidates the changed modules in every Vite environment before
the full reload, so served bytes always match the newly published analysis.

Resolver definition modules remain `.ts` or another JavaScript-family
extension. The Svelte adapter projects usage facts from `.svelte`; it does not
turn a `.svelte` file into a resolver-definition module.

Use an explicit `defaultVariant` on every variant axis for which usage should
prune unselected values. The current core extraction contract publishes
usage-based variant configuration for explicitly defaulted axes. Without a
default, variant output remains conservative.

## Use .attrs() in a component

```svelte
<script lang="ts">
  import { notice } from './definitions';

  interface Props {
    tone?: 'calm' | 'urgent';
    gap?: string;
  }

  let { tone = 'urgent', gap = '13px' }: Props = $props();
  const noticeAttributes = $derived(notice.attrs({ tone, gap }));
</script>

<section {...noticeAttributes}>Dynamic notice</section>
```

`.attrs()` returns a Svelte-spreadable `{ class, style? }` object. The style is
a string, so a runtime `gap` value renders an inline custom property such as
`--animus-gap: 13px`; the delivered stylesheet contains the matching generated
class rule `gap: var(--animus-gap)`.

A literal variant value retains only the selected value when its axis has an
explicit default. A forwarded runtime value is dynamic, so extraction retains
all declared values for that axis. Custom dynamic replacement rules are
usage-dependent: a forwarded `gap` slot emits, while an unreferenced custom
prop does not.

Literal means _written inline in the call's object literal_. The projection
deliberately carries no surrounding declarations, so a value referenced
through an identifier — a local `const`, an imported constant — degrades to
dynamic even when it is statically knowable: its variant axis retains every
declared value and a custom prop takes the runtime custom-property slot.
Write the literal inline when pruning matters.

The callable string form is witnessed identically to `.attrs()`:

```svelte
<script lang="ts">
  import { notice } from './definitions';

  const className = notice({ tone: 'calm' });
</script>

<section class={className}>Calm notice</section>
```

Resolver-level dead-code elimination is deliberately not claimed. An unused
`.asClass()` definition remains conservatively rendered for callable-string
compatibility.

## Supported boundary

The supported resolver witness is a direct `.attrs({ ... })` call — or the
equivalent callable string form `notice({ ... })` — on a lowercase local
binding from an ordinary named, relative import, written in a script scope.
A normal local alias remains supported, a NodeNext-style specifier carrying
the emitted extension (`./definitions.js`) resolves to its source module,
barrel re-exports attribute through the hop — same-name
(`export { notice } from './definitions'`) and renamed
(`export { notice as card } from './definitions'`,
`export { notice as card }` in the defining module) alike — and a resolver
imported in `<script module>` may be called from the instance script:

```ts
import { notice as localNotice } from './definitions';

const attributes = localNotice.attrs({ tone: 'calm' });
```

The following shapes are deliberately unsupported or conservative:

- Default imports, namespace-member access, and string-named imports fail
  closed when they target a resolver — these shapes cannot be reconciled to
  the exact `.asClass()` binding.
- Resolver calls written in the template fragment
  (`<div {...notice.attrs({...})}>`, `{@const a = notice({...})}`) fail
  closed — assign the result to a const in the instance script and spread
  that instead.
- Resolver sources must be relative. Package-specifier and other non-relative
  sources are not attributed by this bounded resolver index.
- The call must receive no argument or one explicit object literal.
  Unresolved arguments and object spreads fail closed rather than silently
  under-emitting.
- Literal pruning through wrapper functions is not inferred. Keep the direct
  resolver call in the Svelte instance script; wrapper-hidden usage remains
  conservative.
- Custom Svelte preprocessors and their source maps are outside the v1
  contract. Use native Svelte syntax and the official Vite plugin's built-in
  TypeScript handling.

The complete working consumer — including SSR, the packed React-absence
proof, and build assertions — lives in the repository at `e2e/svelte-app`.
