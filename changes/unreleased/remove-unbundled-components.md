**Vite builds can drop the CSS of components the bundle never ships.** With `stylesheets: 'split'`, the new `removeUnbundledComponents: true` option removes from the stylesheet's files every rule of a component whose definition no output file includes. Such a component can never render, because a dropped definition is the only place its class enters the page. A rule goes when every selector in it needs such a class, outside a pseudo-class or inside an `:is()` or `:where()` all of whose alternatives need one; a `@media`, `@supports` or `@container` rule left empty goes too. Each changed file is emitted again under the hash of what it now holds. A component `staticCss` declares and the parents of a kept extension stay. A build that also bundles another environment, or that leaves a module external, keeps everything and says why. The build counts a component as removed once one of its rules goes, and reports those whose rules all stayed and why, such as sharing a selector list with a kept component; `verbose: 'trace'` lists each one. Off by default, and development ignores it. Scripts another plugin emits after Animus's `generateBundle` are not seen, and a stylesheet shared with code outside the build, such as micro-frontends or module federation, is not supported with the option on.
